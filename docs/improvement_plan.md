# 补贴管理系统 — 完善规划（乡镇内部使用）

## 一、大户管理

当前大户只是流转记录上的一个标签，缺乏独立视图，管理不便。

### 1.1 大户独立档案
- 大户信息散落在多条流转记录中，查看某大户整体情况需逐条翻阅
- **方案**：`LandTrust` 增加 `large_farmer_id` 外键，关联大户基础信息表
  - 主体名称、类型（家庭农场/合作社/企业/种植大户）
  - 联系人、电话
  - 快速查看该大户名下所有流入土地汇总

### 1.2 大户土地聚合视图
- **方案**：在大户列表页直接展示
  - 流入总面积、涉及流出方户数
  - 各流出方明细可折叠展开
  - 一键导出大户土地台账

---

## 二、流转管理便捷化

### 2.1 流转合同到期提醒
- `land_trust` 有 `end_date` 但没有任何提醒
- **方案**：Dashboard 增加「即将到期流转」卡片，30 天内到期高亮，支持一键续签（复制原记录到新年份）

### 2.2 流转批量续签
- 每年初需将上年流转记录逐条复制到新年份，手工操作量大
- **方案**：勾选多条流转记录，一键批量续签到指定年份

### 2.3 农户流转视图
- HouseholdDetail 中展示该户所有流出/流入记录汇总
- 按年度折叠，一目了然该户的土地变动情况

---

## 三、补贴数据校验增强

### 3.1 跨项目面积联动预检
- 当前预检只查当前补贴类型的面积超限
- **方案**：检查同一农户在"大春+小春+耕地保护"合计面积是否超过可申报上限
- 防止同一块地重复申报不同补贴

### 3.2 预检结果保存与对比
- 每次预检结果关了就没了，无法追溯
- **方案**：预检结果自动保存，支持查看历史预检记录；导入前后对比

### 3.3 常见错误一键修复
- 身份证格式错误、村名不规范等常见问题反复出现
- **方案**：预检结果中提供快捷修复入口（如村名模糊匹配到标准名后一键替换）

---

## 四、查询与导出

### 4.1 补贴发放汇总表
- 向上级报送时需手工汇总
- **方案**：按年度/村/补贴类型导出汇总 Excel
  - 字段：村、组、户数、人数、申报面积、发放金额

### 4.2 超领清单导出
- **方案**：筛出所有超领家庭户，导出含超领面积、涉及补贴的明细表

### 4.3 银行代发格式导出
- 向银行提交发放数据时需调整格式
- **方案**：支持导出银行要求的 Excel 格式（卡号、姓名、金额、摘要）

### 4.4 公示名单打印
- **方案**：按村生成公示表，含户主、补贴项目、面积、金额，直接打印张贴

---

## 五、操作便捷性

### 5.1 批量操作
- 列表增加多选，支持批量删除、批量修改状态

### 5.2 导入模板下载
- 每种补贴类型/流转类型提供 Excel 模板下载，预填表头

### 5.3 操作日志
- 关键操作（导入、批量删除、修改金额）记录操作人和时间，可追溯

## 六、性能优化

### 6.1 家庭户列表查询优化
- **现状**：`list_households` API 返回全量字段（含面积汇总的 20+ 子查询），列表页加载慢
- **方案**：
  - 列表查询只返回列表必要字段（名称、村组、人口、承包面积），面积汇总改为按需加载
  - 为高频筛选字段（village_id、group_no、status）建复合索引

### 6.2 补贴申请列表分页优化
- **现状**：列表查询 join 多张表（FarmerProfile、FamilyHousehold、Village、SubsidyType），千条以上明显变慢
- **方案**：
  - 移除不必要的 join（如列表不展示补贴类型详情时只查 ID）
  - `count()` 查询分离，避免每次翻页都 count
  - 列表接口返回精简字段，详情接口返回完整字段

### 6.3 面积缓存增量更新
- **现状**：`recalc_household_cache` 做全量 SUM 重算，导入 500 条触发 500 次全量重算
- **方案**：
  - 导入后合并 affected_households，去重后批量重算一次
  - 单条 CRUD 使用 `update_cache_incremental`（已实现 O(1) 增量更新，确保所有路径都走增量）

### 6.4 前端列表虚拟滚动
- **现状**：家庭户/补贴列表超过 500 行时渲染明显卡顿
- **方案**：表格组件引入虚拟滚动（只渲染可视区域内的行），万行级流畅

### 6.5 数据库索引补全
- **现状**：部分高频查询字段缺少索引
- **方案**：
  - `subsidy_application(farmer_id, apply_year)` — 已有
  - `subsidy_application(subsidy_type_id, apply_year)` — 补贴项目维度查询
  - `household_area_usage_cache(household_id, year)` — 面积缓存查询
  - `land_trust(trust_year, is_active)` — 流转年度查询
  - `farmer_profile(id_card)` — 身份证查询（已有）

### 6.6 API 响应瘦身
- **现状**：部分接口返回全模型字段，前端只用其中几个
- **方案**：
  - Dashboard 统计接口只返回聚合值，不返回明细
  - 下拉选项接口（村列表、户列表）只返回 id + 名称
  - 列表接口和详情接口分离

### 6.7 流转列表懒加载面积汇总
- **现状**：LandTrustPage 每次切换筛选条件都重新请求面积汇总（含多个 SUM 子查询）
- **方案**：面积汇总改为点击具体户时才加载，列表仅展示流转记录本身

---

## 七、数据维护

### 7.1 软删除与恢复
- 误删数据无法恢复
- **方案**：关键表增加 `is_deleted` 字段，删除标记而非物理删除，支持恢复

### 7.2 农户快速去重合并
- 同一人可能因身份证录入差异存在多条农户记录
- **方案**：身份证相似度检测，提示可能的重复记录，支持合并

## 优先级

| 优先级 | 功能 | 理由 |
|--------|------|------|
| **P0** | 跨项目面积联动预检 | 防止重复申报，直接关系补贴资金准确性 |
| **P0** | 面积缓存去重批量重算 | 导入 500 条从 500 次全量重算优化为 1 次 |
| **P0** | 流转批量续签 | 每年必做操作，当前逐条处理效率极低 |
| **P1** | 列表接口精简 + 索引补全 | 数据量增长后直接影响日常操作流畅度 |
| **P1** | 大户土地聚合视图 | 大户管理是日常高频需求 |
| **P1** | 补贴发放汇总表 | 向上级报送刚需 |
| **P1** | 流转到期提醒 | 避免过期流转影响面积计算 |
| **P1** | 银行代发格式导出 | 打通发放最后一环 |
| **P2** | 前端虚拟滚动 | 大户量场景列表流畅滚动 |
| **P2** | 流转列表懒加载面积汇总 | 减少不必要的聚合查询 |
| **P2** | 公示名单打印 | 村务公开需求 |
| **P2** | 农户流转视图 | 提升信息查询效率 |
| **P2** | 操作日志 | 内部管理规范性 |
| **P3** | 批量操作/软删除/模板下载/重复合并 | 锦上添花 |
