## Village Group 重复数据清理

### 问题描述
用户报告在 village_group 表中，"两河村一组" 等村组存在重复数据，每个村组有两个ID（如ID 73和124）。需要确保 "xx村xx组" 这种fullname在表中是唯一的。

### 分析发现
1. **数据情况**:
   - 总共147条村组记录
   - 40个村组有重复数据（每个村组2条记录）
   - 每个村组的两个ID中，较小的ID引用家庭户较多，较大的ID引用较少
   - 例如："两河村一组"有ID 73（43户）和ID 124（1户）

2. **影响范围**:
   - 所有重复的村组都被 family_household 表引用
   - 需要迁移家庭户数据，确保引用完整性

### 解决方案
采用以下策略进行清理：
1. 对于每个重复的村组，保留引用最多的ID
2. 将引用较少的ID的家庭户迁移到保留的ID
3. 删除无引用的重复村组记录
4. 添加数据库约束防止未来重复

### 执行过程
1. **数据备份**: 创建了数据备份文件
2. **逐条处理**:
   - 两河村一组: 保留 ID 73, 迁移 1户 从 ID 124, 删除 ID 124
   - 两河村二组: 保留 ID 74, 迁移 8户 从 ID 125, 删除 ID 125
   - ... (其他38个村组类似处理)
3. **验证**: 迁移后验证无重复数据和无孤儿家庭户
4. **约束添加**: 在 models.py 中添加唯一约束，在数据库创建唯一索引

### 结果统计
- **迁移家庭户**: 110 个
- **删除村组记录**: 40 条
- **剩余村组总数**: 107 个
- **重复村组数**: 0 个

### 预防措施
1. 更新 `models.py` 中 `VillageGroup` 类:
   ```python
   __table_args__ = (
       UniqueConstraint('full_name', name='uq_village_group_full_name'),
   )
   ```
2. 在数据库中创建唯一索引 `uq_village_group_full_name`
3. 现在任何尝试插入重复村组记录的操作都会被数据库阻止

### 验证结果
1. ✓ 无重复的村组记录
2. ✓ 无孤儿家庭户（所有家庭户都有有效的村组引用）
3. ✓ 数据库约束生效，阻止重复数据插入

### 文件修改
1. **models.py**: 添加了 VillageGroup 的唯一约束定义
2. **数据库**: 创建了唯一索引 uq_village_group_full_name
3. **清理报告**: 创建了 village_group_cleanup_report.md
4. **清理脚本**: 创建了多个清理脚本供未来参考

### 注意事项
1. 所有业务逻辑依赖的村组ID现在都是唯一的
2. 历史数据已被清理，确保数据一致性
3. 未来导入或创建村组数据时，系统会自动防止重复

## 用户界面优化（2026-03-24 17:45）

### 需求背景
用户反馈两个主要问题：
1. 选择不同年份页面后，刷新页面时会丢失年份选择，需要重新选择
2. 人员导入界面缺乏数据筛选功能，批量选择删除功能需要完善

### 解决方案

#### 1. 年份选择持久化
**问题**: 刷新页面或从子页面返回时，年份选择状态丢失
**解决方案**: 使用URL参数保存年份选择
- 在主项目页面（SubsidyProjectsPage.tsx）添加 `useLocation` 和 `useNavigate` hooks
- 修改年份选择器的 `onChange` 处理函数，同时更新状态和URL参数
- 从URL参数 `?year=2024` 读取并恢复年份选择

#### 2. 人员导入界面数据筛选功能增强
**问题**: 无法按村庄、发放状态、金额范围、日期范围等进行筛选
**解决方案**: 添加完整的数据筛选面板

- **批量删除**: 当有选中记录时，显示批量删除按钮
- **确认对话框**: 删除前显示确认对话框，防止误操作
